AGENT-L est un langage agentique déclaratif, analysé statiquement et interprété. Un programme ne décrit pas une suite d’appels : il déclare **ce que l’agent poursuit**, **ce qu’il perçoit**, **ce qu’il peut faire** et **ce qu’il ne doit jamais faire**.

Le LLM propose. Le runtime décide.

## Pourquoi AGENT-L

Dans un agent conversationnel classique, objectifs, règles et outils finissent souvent dans le même prompt. Ils deviennent difficiles à inspecter et encore plus difficiles à tester. AGENT-L les transforme en primitives explicites.

```text soc_analyst.agent
AGENT SOC_ANALYST {
    GOAL containment { MAINTAIN threat.status == contained }

    OBSERVE { threat.status asset.criticality suspected_host }

    TOOL isolate_endpoint {
        INPUT  { host: String BIND suspected_host }
        RISK   { operational = HIGH }
        EFFECT { threat.status = contained }
        COST   8
    }

    POLICY {
        DEFAULT DENY
        ALLOW isolate_endpoint IF threat.confirmed == yes
        NEVER isolate_endpoint WHEN asset.criticality == CRITICAL
    }
}
```

## Nouveautés de la v1.12

<Columns cols={2}>
  <Card title="agentl mutate" icon="dna" href="/core/quality-gates">
    Retire chaque `NEVER`, `DENY`, `REQUIRE APPROVAL` et la garde de chaque `ALLOW … WHEN`, rejoue les scénarios et liste les règles qu’aucun test ne défend.
  </Card>
  <Card title="Une garde de provenance se teste" icon="fingerprint" href="/core/provenance">
    `GIVEN { ip = "…" UNTRUSTED }` pose une valeur écrite par un tiers ; `scenario.refuse.<outil> = yes` fait refuser le validateur simulé.
  </Card>
  <Card title="Le refus est un fait" icon="octagon-x" href="/core/policies">
    `tools.<outil>.denied`, `.unapproved` et `.refused` se lisent dans le programme ; `agentl.Refused` refuse sans compter comme une panne.
  </Card>
  <Card title="Un VERIFY en échec ne fige plus l’agent" icon="shield-alert" href="/core/verifier">
    Les règles `DECIDE`, `EVENT` et `MESSAGE` des ticks suivants partent normalement, y compris sous `ON VERIFY.FAIL`. Rupture annoncée pour les journaux de la 1.8.
  </Card>
</Columns>

## Nouveautés de la v1.11

## Deux façons de travailler

<Tabs>
  <Tab title="Core / CLI" icon="terminal">
    Écrivez les couples normatifs `X.agent` / `X.py`, puis passez-les dans la chaîne de qualité et le runtime Python.

    ```bash
    agentl check agent.agent
    agentl test agent.agent
    agentl verify agent.agent
    agentl boundary agent.agent
    agentl run agent.agent
    ```
  </Tab>
  <Tab title="Studio" icon="panels-top-left">
    Gérez les projets, les skills, les propositions de l’agent auteur, les exécutions et leurs traces depuis une application locale.

    ```bash
    cd STUDIO
    python3 -m pip install -r requirements.txt
    npm run install:ui && npm run build && npm start
    ```
  </Tab>
</Tabs>

<Note>
  Le Core fonctionne avec Python 3.10+ et la bibliothèque standard uniquement. Studio ajoute FastAPI, Uvicorn et l’interface React.
</Note>
